# Data

This folder is the **data foundation** for OreSight.

OreSight is a hackathon MVP for mine reserve intelligence. It is **not** a production mining system and it does **not** contain real mine operational records.

## Labels (required)

| Kind | How it must be labeled |
| --- | --- |
| Synthetic operational / geological tables | Filenames and column metadata must say `synthetic`. Never describe them as real MOIL (or any operator) data. |
| Public or user-supplied files | Keep original provenance in this README or a sidecar note. Do not mix them with synthetic tables without a `source` field. |

## Layout

- `raw/` — original inputs as ingested. Do not overwrite. Prefer one file per table.
- `processed/` — schema-stable tables for later ML modules. Same column names and dtypes across regenerations.

## Reproducibility

All synthetic generation must use a **fixed random seed** (default: `42`) so reruns produce the same tables.

## Schema contract

Later modules consume processed tables in this order:

`PRISM → EAR → PULSE → RISK → SHAP → NUDGE → FastAPI → React`

Do not rename columns or change units after Phase 1 without updating every downstream consumer.

Column-level schemas, units, and provenance: [`raw/DATA_DICTIONARY.md`](raw/DATA_DICTIONARY.md).

## Phase 1 tables (`data/raw/`)

Generated by `python scripts/generate_data.py` (seed `42`). **Synthetic demonstration data only — not real MOIL / NGDR data.**

| File | Role |
| --- | --- |
| boreholes.csv | Spatially correlated Mn composites on a folded ore zone |
| blocks.csv | 3D block centroids, volume, density |
| production.csv | Daily planned vs actual tonnes |
| equipment.csv | Daily fleet downtime / availability |
| blast.csv | Daily blasts and delays |
| development.csv | Daily development metres |
| manpower.csv | Daily labour and shifts |
| weather.csv | Monsoon-like rainfall and related indices |

## What is not in this phase

No processed ML feature tables yet. No models, APIs, dashboards, Kriging, forecasting, SHAP, or optimization.
